# AI for better life In ustc 轻量团队仓库设计

## 1. 背景

团队参加中国科学技术大学“一〇七”杯算力与智能体开发大赛，报名组别为本科生组，参赛赛道为智能体赛道。队伍名称为 `AI for better life In ustc`，现有三名本科生成员，由队长负责主要协调工作。团队尚处于选题和方案讨论阶段，需要一个简单、可靠的私有 GitHub 仓库作为共同资料和后续代码的唯一共享位置。

## 2. 目标

- 在 GitHub 账号 `xytsakura` 下创建私有仓库 `ai-for-better-life-in-ustc`。
- 让团队成员在被邀请后都可以读取和写入仓库。
- 通过 Git 提交记录保留每次修改的作者、时间、说明和文件差异。
- 用清晰的 `README.md` 介绍团队背景、参赛信息、总体目标、当前阶段和协作方式。
- 保留已整理的官方比赛要求，方便团队随时核对。
- 为后续方案文档和项目代码预留自然扩展空间，但当前不提前建立复杂目录。

## 3. 非目标

- 不创建 GitHub Projects 或任务看板。
- 不配置 Issue 模板、Pull Request 模板、里程碑或复杂分支流程。
- 不配置持续集成、自动发布或其他自动化。
- 不在当前阶段确定具体智能体选题、技术栈或系统架构。
- 不在本次创建过程中邀请队友；待队长提供 GitHub 用户名后再添加协作者。

## 4. 仓库结构

初始仓库只保留必要文件：

```text
ai-for-better-life-in-ustc/
├── README.md
├── 比赛要求.md
├── agent.md
└── docs/
    └── superpowers/
        └── specs/
            └── 2026-07-19-lightweight-team-repository-design.md
```

各文件职责如下：

- `README.md`：面向团队成员的项目主页，说明队伍、赛道、目标、状态和最小协作方法。
- `比赛要求.md`：保存公众号原文链接及赛事规则整理，不与团队方案混写。
- `agent.md`：记录本工作目录的 Agent 协作约定和已确认事实。
- 本设计文档：记录仓库创建范围和取舍，便于以后理解初始决策。

形成成熟选题后，再按实际需要增加方案设计、会议记录、代码、测试或演示材料；不提前创建空目录。

## 5. README 内容设计

`README.md` 使用中文，包含以下内容：

1. 队伍名称：`AI for better life In ustc`。
2. 参赛信息：三名本科生成员、本科生组、智能体赛道。
3. 项目背景：围绕智慧科大校园场景讨论和开发能够改善学习、科研、校园生活或服务体验的智能体应用。
4. 总体目标：从真实校园问题出发，形成兼具实用性、创新性、技术难度和完成度的参赛作品。
5. 当前阶段：报名已完成（以队长确认的信息为准），正在讨论选题和方案。
6. 协作方式：拉取最新内容、完成修改、提交并推送；重要方案先在群内讨论。
7. 安全提醒：不得提交 API key、密码、个人敏感信息、未脱敏数据或来源不明的受限材料。

README 不虚构具体成员姓名、明确分工、成熟方案或尚未决定的技术路线。

## 6. Git 与 GitHub 设置

- 默认分支使用 `main`。
- 仓库可见性设置为 `private`。
- 首次推送包含 README、比赛要求、Agent 约定和本设计记录。
- 不启用复杂分支保护；团队规模较小，成员可直接在 `main` 分支提交和推送。
- 队友用户名尚未提供，因此仓库创建后先由队长独占访问；提供用户名后再添加两名具有写权限的协作者并验证访问。
- 仓库描述使用简洁中文，说明其为“一〇七”杯智能体赛道本科生队伍协作仓库。
- 创建前先验证当前 GitHub 登录账号和目标仓库是否存在；若目标已存在且不是本项目，不覆盖、不删除、不自动改名，立即停止并报告，由队长决定后续名称。

## 7. 协作流程

日常协作采用最小流程：

1. 修改前先拉取远程最新内容。
2. 在本地修改文档或代码。
3. 使用能说明本次变化的提交信息创建提交。
4. 推送到 GitHub，其他成员可以查看提交记录和文件差异。
5. 重要选题、方案取舍和冲突优先在团队群讨论，再将结论写入仓库。

发生推送冲突时，先拉取并检查双方修改，再合并；不覆盖或丢弃其他成员已经提交的工作。

## 8. 验收标准

- GitHub 上存在 `xytsakura/ai-for-better-life-in-ustc` 仓库。
- 仓库明确显示为私有，默认分支为 `main`。
- 本地目录已与该远程仓库关联。
- GitHub 仓库能正常显示 README 首页。
- README 中的队伍名称、组别、赛道、报名状态和当前阶段准确，其中报名已完成以队长确认的信息为准。
- `比赛要求.md`、`agent.md` 和本设计文档均已推送。
- Git 历史中能够查看初始提交及其文件差异。
- 仓库中不存在密钥、密码或个人敏感信息。

队友的写权限邀请与验证属于后续验收项，待队长提供 GitHub 用户名后执行，不阻塞首次创建。

## 9. 风险与处理

- 仓库名称或所属账号冲突：创建前查询目标仓库是否已存在；若存在则先检查是否为本项目，不覆盖无关仓库。
- Git 作者信息未配置：仅在当前仓库配置与 GitHub 账号匹配的作者信息，避免修改用户的全局设置。
- 队友暂时无法访问：这是当前已知状态；待提供 GitHub 用户名后再邀请并验证权限。
- 未来文件增多导致直接向 `main` 推送产生冲突：当前接受该简化方案；如协作频率或代码复杂度明显增加，再引入功能分支或 Pull Request。
