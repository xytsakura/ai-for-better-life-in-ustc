# 2026-07-19 项目方案会议记录

## 会议结论

团队确定采用“集成框架”模式建设 AI Agent 项目。项目不只实现某一个校园能力，而是搭建统一协议和平台作为统筹层，将不同团队开发、面向校园生活的 Agent 接入同一入口，形成一站式服务体验。

该方向希望解决校园 Agent 功能分散、入口分散和互操作困难的问题，产品形态可类比“我的科大”对校园服务的统一集成，但本项目的核心对象是可独立运行的 AI Agent。

## 核心决策

1. 项目核心是协议调度层和集成框架，而不是单个课程助手。
2. 第一版采用白名单方式真实接入第三方 Agent，不建设完全开放的 Agent 市场。
3. 比赛 Demo 包含两个独立 Agent：课程评价 Deep Research Agent、课程资料与复习 Agent。
4. 课程相关 Demo 初期优先接入 USTC 评课社区，同时补充课程官方主页和经许可的 GitHub 资源。
5. 数据缓存以课程为基本单元，支持摘要复用和新内容增量更新。
6. 公共课程知识库与用户自行上传的个人资料必须隔离。

## Demo 设想

### 课程评价 Deep Research

用户使用自然语言查询课程或教师，系统聚合课程基本信息、课程要求、不同学期评价和允许访问的附件，形成带来源、时间和不确定性说明的调研报告，帮助学生选课。

### 课程资料与复习助手

系统整理课程主页、经许可的 GitHub 资源、允许使用的课程附件以及用户自行上传的资料，为每门课建立可复用知识库，提供带引用的检索和复习问答。

## 技术调研结论

- 独立 Agent 之间使用 A2A；
- Agent 与数据源、工具之间使用 MCP；
- 平台普通 HTTP 接口使用 OpenAPI 3.1 和 JSON Schema 2020-12；
- 评课社区采用会话 Cookie + CSRF，没有可共享的通用用户 API token；
- 登录限定内容不得依赖队长共享账号，优先采用用户本地授权连接器或争取站点维护者提供只读接口。
