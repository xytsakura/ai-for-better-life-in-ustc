# v0.4 Personal Main Agent 单跳编排审计

> 日期：2026-07-19
> 状态：通过，可作为当前设计发布判定
> 审计对象：`v0.4` 设计与任务文档，不代表代码、部署、模型兼容性或第三方数据授权已经验证。

## 1. 审计结论

`v0.4` 已形成可实施、可测试的两层单跳架构：

```text
用户
  -> Personal Main Agent
  -> Gateway 渐进披露 accepted + enabled Specialist
  -> Gateway 创建唯一 depth=1 ChildTask 与最小上下文授权
  -> 一个 Specialist
  -> SpecialistArtifact
  -> Gateway 确定性校验
  -> Main Agent 生成 MainAnswerArtifact
  -> Gateway 确定性校验后返回用户
```

当前发布判定为 **Approved**。没有剩余 P0/P1/P2 文档阻塞项，可以交给三名队员评审、分工和编写实施计划。

本结论只表示架构、契约、安全边界和 MVP 范围在文档层面闭合。仓库仍处于设计阶段，不能声称 Agent、协议、RAG、Connector、缓存或安全测试已经实现。

## 2. 冻结边界

本轮审计确认以下约束不得在实现时静默放宽：

1. Personal Main Agent 是普通用户唯一入口、唯一语义选择者和最终回答生成者。
2. Gateway 是确定性控制面，只做目录过滤、授权、父子任务、A2A、预算、限深、取消、校验和审计，不做语义路由或答案改写。
3. Main 默认只看到平台生成的 `CatalogSummary`，准备调用时才读取 `CapabilityDetail`；完整 `GovernanceDetail` 仅管理员可见。
4. 每个 Main turn 最多一个 `depth=1` ChildTask；Specialist `can_delegate=false`，禁止第二 child、递归、fan-out、并行和 Specialist 相互调用。
5. `input_required` 由 Main 向用户补问并继续同一个 child，不创建第二个 ChildTask。
6. Main 只提交不含服务端 ID 的 `SpecialistInvokeRequest`；Gateway 原子生成 ChildTaskRecord、ContextGrant、AuthorizedContextBundle 和 `SpecialistTaskEnvelope`。
7. Specialist 只获得字段级、用途绑定、接收方绑定、短 TTL 的最小上下文；完整 Profile、ModelProfile、会话、记忆、API key、Cookie 和 CSRF 不进入第三方 payload。
8. Specialist 只返回 `SpecialistArtifact`，不能直接答复用户、写长期记忆或发起新任务。
9. Main 生成的 `MainAnswerArtifact` 必须保留引用、限制、data scope、cache level 和唯一 child lineage，并经 Gateway 确定性校验后返回用户。
10. 硬 MVP 先使用平台/团队受控测试模型；完整 CLI Runner 是满足主链稳定、安全基线和排期条件后最多两天的增强 spike。

## 3. 审计范围

本轮覆盖：

- README、总体架构、项目路线图和当前工作目录约定；
- Gateway、课程评价 Specialist、课程资料 RAG Specialist、个人 Agent Harness、Main Agent 单跳编排五份设计；
- ADR-0001 至 ADR-0004 与三份当前规格；
- A2A/MCP、竞品、评课社区、模型/BYOK/Runner 调研；
- 威胁模型、公共 QA/L1-L5 缓存、个人记忆写回和第三方内容边界；
- 本地 Markdown 链接、JSON/Schema 示例、旧版术语、敏感信息和 Git diff 质量。

审计分为三条相互独立的只读路径：

1. 架构审计：角色职责、主链、渐进披露、最终回答和 MVP 可实现性；
2. 契约与安全审计：任务、授权、Artifact、状态、取消、缓存和 API audience；
3. 范围与一致性审计：版本、术语、Runner、Demo 数量、数据授权和版权边界。

主 Agent 负责合并发现、修改、机器校验，并把修复后的同一工作区重新交给三路 reviewer 复审。

## 4. 第一轮发现与修复

| 严重度 | 发现 | 修复 | 复审状态 |
|---|---|---|---|
| P1 | 总契约与两个 Demo 的 `SpecialistArtifact` 字段、状态和 ID 不兼容 | 建立唯一 canonical Schema，统一 `schema_version`、`skill_id`、`status`、结构化 answer、evidence、usage、generated_at 与 ID pattern | 已关闭 |
| P1 | Main 请求和 Gateway 投递对象混在一起，Grant ID 生命周期自相矛盾 | 拆分 `SpecialistInvokeRequest` 与 `SpecialistTaskEnvelope`；Main 不提交服务端 ID，Gateway 原子生成 child/grant/bundle | 已关闭 |
| P1 | ContextGrant 文字要求防重放和绑定 child，但核心 Schema 缺少版本、attempt、nonce、egress 等字段 | 扩展 ContextGrant，并新增 `AuthorizedContextBundle` Schema，绑定 root/child/attempt/Specialist/version/skill/匿名主体/egress/TTL | 已关闭 |
| P1 | 中央 `data_scope` 单值无法表达 RAG 的 public + private 混合检索 | InvokeRequest、Grant、Bundle 和 Artifact 统一支持 scope 数组 | 已关闭 |
| P1 | RAG 输入不足会创建新 child，违反每回合一个 child | 统一为 `input_required`，由 Main 补问并继续原 child | 已关闭 |
| P1 | RAG 与 Harness 局部仍把完整 CLI Runner 写成硬 MVP | 改为条件增强；硬 MVP 只要求平台/团队测试模型闭环 | 已关闭 |
| P1 | 通用 task/Agent API 看起来可由普通用户调用，可能绕过 Main | 通用任务迁到 `/v1/internal/tasks`，完整 Agent 列表迁到 `/v1/admin/agents`，区分 user/Main/internal/admin/Specialist audience | 已关闭 |
| P1 | Main 最终结果可能绕过 Gateway 输出治理 | 增加 MainAnswerArtifact 提交与确定性校验；Gateway 不改写语义 | 已关闭 |
| P2 | CapabilityDetail 只有自然语言清单，可能重新注入第三方长描述 | 增加受长度、字段白名单、版本和快照摘要约束的 Schema | 已关闭 |
| P2 | Catalog 示例缺少确认和最近验收时间，部分角色仍用旧 Agent 命名 | 补齐 required 字段，统一当前文档的 Specialist 命名 | 已关闭 |

## 6. 机器校验

- 所有本地 Markdown 链接可解析到现有文件，缺失数为 0；
- 所有 fenced JSON block 可被 JSON 解析器读取；
- 当前 19 个 JSON Schema block 通过本地结构检查；
- 课程评价与课程资料的 2 个 `SpecialistTaskEnvelope` 和 2 个 `SpecialistArtifact` 示例均通过中央 Schema 的 required、类型、ID、枚举与 `additionalProperties` 校验；
- `git diff --check` 通过，仅有 Windows LF/CRLF 提示；
- 未发现 merge marker、乱码、TODO/FIXME/TBD 占位符；
- 高置信度 API key、GitHub token、Cookie、CSRF 和会话凭据扫描为 0 命中；
- 当前文档明确标注“代码尚未实现”，没有伪报可运行结果。

当前机器只有旧版 Python `jsonschema`，不能完整执行 Draft 2020-12 的 `const`、`if/then` 等全部语义。本轮已人工复核这些关键约束；实施第一周仍必须使用新版 Draft 2020-12 validator 在 CI 中编译 Schema，并加入正反 fixture。

## 7. 残余风险

| 风险 | 当前控制 | 进入实现的门槛 |
|---|---|---|
| A2A/MCP SDK 与文档语义可能存在版本差异 | 锁定协议基线，不跟随 latest 静默升级 | 两天 spike 后锁依赖与 binding，跑状态/取消/追问兼容测试 |
| Main Agent 可能误调用或漏调用 Specialist | 固定 Catalog/CapabilityDetail 和路由指标 | 建立固定意图集，选择准确率不低于 90%，不必要调用率不高于 10% |
| LLM 可能丢失 Specialist 引用或限制 | MainAnswerArtifact required + Gateway 确定性校验 | 固定忠实度评测，关键引用/限制保留率 100% |
| 评课社区登录内容与附件授权未解决 | 公开模式优先，登录限定内容不进入服务器或共享缓存 | 获得明确授权且威胁测试通过，否则保持公开/本地降级 |
| 公共 QA 可能被污染 | 版本化 key、public-only、引用/DLP/提示注入校验、撤回失效 | 发布流程加入人工复核、固定评测和 60 秒级联失效测试 |
| 私人信息向远端模型或第三方 Specialist 外发 | ContextGrant/Bundle、egress policy、逐次确认和 audience 隔离 | 正反权限测试中跨用户和未确认外发成功数为 0 |
| 三人团队排期不足 | Main 到一个 Specialist 纵向闭环优先，Runner 条件增强 | 严格执行路线图停止条件，不以 mock 掩盖缺失的父子任务或授权 |
