# v0.3 个人 Agent Harness 集成审计

> 日期：2026-07-19
> 状态：通过，可交给团队审阅并进入实施计划
> 审计对象：`v0.3` 设计文档，不代表代码、部署或第三方授权已经验证。

## 1. 审计范围

本轮审计覆盖：

- README、总体架构、路线图和当前工作目录约定；
- Gateway、课程评价、课程资料 RAG、个人 Agent Harness 四份设计；
- ADR-0002、ADR-0003 与两份正式规格；
- 模型 provider/BYOK/Runner 调研和平台威胁模型；
- A2A/MCP/ModelAdapter 边界、Profile/Runner/OpenAPI 契约、L1-L5 缓存、MVP 与后置范围；
- 本地 Markdown 链接、JSON 示例、凭据模式和 Git diff 质量。

审计分为三条独立只读路径：

1. 规格与契约审计：检查数据流、Schema、接口、状态、MVP 验收和降级条件；
2. 安全与隐私审计：检查 BYOK、数据 egress、provider allowlist、Runner、成本、缓存与 DLP；
3. 跨文档一致性审计：检查版本、术语、模块数量、Demo 范围和未实现能力措辞。

每条路径由独立 reviewer 输出 findings，主 Agent 负责取舍、修改、机器校验和复审；发现修复后重新派发原 reviewer，直到批准。

## 2. 发布结论

审计后保留的产品命题是：

> 平台提供统一校园 Agent Harness、模板、工具、知识资源、缓存和调度能力；用户通过 AgentProfile 选择模型、知识空间、记忆、预算与执行位置。两个内部课程 Demo 仍是独立 A2A 服务，但复用 Harness Core；第三方独立 Agent 继续走 A2A，Agent 内部工具继续走 MCP，模型 provider 只属于内部 adapter。

推荐的混合执行模式成立：

- 公共任务可使用平台/团队受控测试模型；
- 普通用户真实 BYOK 的比赛主演示路径是只出站本地 Runner；
- 比赛 MVP 不收集普通用户真实托管 key，不开放任意 `base_url`；
- provider、key 归属和本地/云执行不静默切换；
- 不同模型共享公开来源、解析、索引和证据，私人生成、记忆与 usage 按用户隔离。

当前文档达到“可供三名队员评审、分工和编写实施计划”的标准。代码尚未实现，不能把接口和安全验收写成已运行能力。

## 3. 发现与修复

| 严重度 | 发现 | 修复 | 状态 |
|---|---|---|---|
| P1 | Runner/Profile 已进入 MVP，但 Gateway 缺少配对、lease、结果与 usage 接口 | 增加 Profile/ModelProfile、execution 查询、Runner pairing、next/claim/heartbeat/events/complete REST 契约及 RunnerLease、RunnerResult、UsageRecord Schema | 已关闭并复审通过 |
| P2 | AgentTemplate、AgentProfile、ModelProfile、CapabilitySnapshot 只有示例，没有最小 JSON Schema | 补 required、ID pattern、枚举、owner、版本兼容、条件约束和 `additionalProperties=false` | 已关闭并复审通过 |
| P2 | 路由示例的 runtime/cache 字段与 TaskRequest 不同形 | 统一为 `execution_preferences`，并明确这是身份校验后的内部归一化输入 | 已关闭并复审通过 |
| P2 | Gateway 仍有可能被理解为自动 Agent fallback | 删除 `fallback_agent_ids`；Agent 不可达只重试一次后失败，切换必须确认并创建新任务 | 已关闭并复审通过 |
| P2 | Runner `canceled/cancelled` 与 `subject_id` 契约不一致 | 统一平台状态为 `cancelled`；RunnerLease/UsageRecord 增加随机不透明 `subject_id` 并校验 token/task owner 绑定 | 已关闭并复审通过 |
| P3 | TaskRequest `metadata` 允许任意字段，可能成为 Cookie/API key 旁路 | 只允许 `demo_scene`、`client_request_id`，限制长度并增加 fake secret/base URL/受限 URL DLP 负例 | 已关闭并复审通过 |
| P3 | README Mermaid 重复使用节点 ID `P` | 拆分为 `PROFILE` 和 `PRIVATE_KB` | 已关闭 |
| P3 | 威胁模型版本和主规格 Demo 范围容易误读 | 威胁模型升到 `0.3`；明确只有两个业务 Demo，外部通知与双运行时只是接入/可替换性验证 | 已关闭并复审通过 |

此外主动修正了一处架构表达：两个内部课程 Demo 继续按服务粒度发布 Agent Card 与 A2A endpoint，但内部复用 Harness Core；个人用户/Profile 不发布独立 Agent Card。这同时满足原外部接入证明与新个人 Agent 方向。

## 4. 安全判定

以下控制已经进入设计和验收：

- 数据 scope 先于模型路由；`private`、`local_authenticated` 默认本地执行；
- 托管密钥仅以用户拥有的 `secret_ref` 存在，普通用户比赛路径不托管真实 key；
- provider/base URL allowlist，MVP 禁止任意用户 URL；
- Runner token、nonce、lease_seq、过期、版本、原子认领、幂等与结果重校验；
- key 撤销/轮换使排队、重试和未完成 lease 失效；
- 每用户/provider 的 token、费用、并发、RPM/TPM、重试与工具步数限制；
- L1-L5 缓存分层，用户 BYOK 默认不能晋升公共 L4；
- 日志、trace、事件、Artifact、数据库导出和浏览器响应的 DLP 负例；
- Profile、ModelProfile、私人记忆与 L5 跨用户零命中测试。

安全 reviewer 复审后未发现剩余 P0-P2。实现时仍必须在 Schema 校验之外扫描 `demo_scene`、`client_request_id` 的值，不能因为键名被允许就信任内容。

## 5. 机器校验

- 所有本地 Markdown 链接可解析到现有文件；
- 所有 `json` fenced code block 可被 JSON 解析器读取；
- 新增模型调研实际引用的 OpenAI SDK、DeepSeek、Anthropic 和 A2A 主来源 URL 可访问；
- 高置信度 API key/GitHub token 模式扫描为零命中；
- `git diff --check` 通过；
- 当前文档没有把代码、SDK 兼容、Runner 安全或第三方授权写成已实现。

本轮只验证了 JSON 语法，没有在本地安装 Draft 2020-12 metaschema 编译器。实施前必须把 Schema 落到 `packages/schemas/agent-runtime/`，使用锁定版本 validator 完成 metaschema、自身示例、非法样例和兼容回归测试。

## 6. 残余风险

| 风险 | 当前状态 | 下一步门槛 |
|---|---|---|
| OpenAI-compatible 不等于能力等价 | 已用 CapabilitySnapshot 限制，尚未真实探测 | 两天 spike 验证 streaming、tools、JSON、usage 和错误语义 |
| 本地 Runner 契约尚无代码 | 接口与攻击用例已定义 | 实现单设备 CLI Runner，跑通断线、重放、撤销与跨用户拒绝 |
| 模型价格、额度和学校 API 未确认 | Usage Ledger 可不显示未知费用 | 实施当天核对官方政策，未知价格只展示 token |
| 评课社区登录内容和附件授权 | 默认本地且不入共享系统 | 联系维护者；无明确授权继续公开短缓存降级 |
| 三人团队时间不足 | ADR-0003 有 2026-07-27 降级门槛 | Harness spike 失败时保留规格/接口验证，不阻塞原三条主线 |
| Schema 只完成文档级检查 | JSON 语法通过，未编译 metaschema | 实施第一周加入 validator 和正反 fixture |
