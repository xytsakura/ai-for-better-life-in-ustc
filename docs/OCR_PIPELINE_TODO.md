# 统一 OCR 处理链路状态与后续待办

## 背景与目标

课程资料原先主要依赖 PyMuPDF 提取 PDF 自带文本层。抽样审计确认，扫描版 PDF、图片拼接资料、手写笔记和公式密集页面中存在空文本、乱码、私用区符号和公式结构损坏，而且部分低质量页面曾被误标为 `text_ok`。

2026-08-03 已接入内网 DeepSeek-OCR-2 服务，并完成数学分析 B1 全部 25 份唯一 PDF、510 页的 Markdown OCR 回填。OCR 文本以 `<原文件名>.ocr.md` sidecar 保存，带 PDF SHA-256、页数、模型、模式、DPI 和稳定页边界；RAG 使用 sidecar 文本，引用与预览仍使用原 PDF。当前索引为 500 个可检索页、10 个空白页、686 个分块。

批处理工具位于 `apps/course-agent/scripts/ocr_backfill.py`，支持多个 OCR endpoint、逐 endpoint 串行、跨 endpoint 并行、页级缓存、超时重试、断点续跑和原子发布。`course_agent.ingestion.PyMuPDFParser` 只接受哈希与页数均匹配且页面完整的 sidecar，否则回退到 PyMuPDF。

## 实施清单

### 1. OCR 服务部署

- [x] 在服务器上部署 DeepSeek-OCR-2 推理服务并固定模型标识。
- [x] 提供仅经本地 SSH 隧道访问的 HTTP API，不直接暴露到公网。
- [x] 支持单页图片输入，并返回识别结果和明确的 HTTP 错误。
- [x] 实现逐 endpoint 单请求、超时、有限重试、页级缓存和断点续跑。
- [ ] 记录延迟、失败率和模型版本，不在日志中记录原始私有资料或完整识别正文。

### 2. 最小 API 契约

- [ ] 请求至少包含：`job_id`、`document_id`、`page_number`、页面图片、语言提示和输出格式。
- [ ] 响应至少包含：`status`、`plain_text`、`markdown`、`confidence`、`model_version`、`config_version` 和错误码。
- [ ] 预留版面块、公式、表格、图片区域及其坐标字段，第一版允许为空。
- [ ] 同一 `document_id + page_number + model_version + config_version` 可幂等重试，不重复生成多份结果。

### 3. 导入流程接入

- [ ] 对 `needs_ocr` 页面自动创建 OCR 后台任务。
- [ ] 对 `needs_review` 页面提供人工触发 OCR 的入口，避免无意义地重复处理可读页面。
- [x] 将 PDF 页面按受控 DPI 渲染为 PNG；服务端限制上传大小。
- [x] 保存页级 OCR 结果、模型版本、模式、DPI、源文件哈希和原始页码。
- [x] OCR 成功后重新切块、重建全文索引，并使旧切块失效。
- [ ] OCR 失败时保留原文件和失败状态，支持重试、取消和进度查询。
- [ ] 删除文档时同步删除 OCR 结果、索引、缓存和临时页面图片。

### 4. 质量验证

- [ ] 建立小型验收集：中文印刷体、中文手写体、扫描试卷、公式、表格、双栏排版和图文混排。
- [ ] 检查文字准确性，以及标题、段落、公式和表格的结构保留情况。
- [x] 检查识别片段能否回到原 PDF 文件名和页码，引用链未改变。
- [ ] 对低置信度结果标记 `needs_review`，不得直接伪装成高质量资料。
- [ ] 记录单页延迟、批量吞吐、失败率和显存占用，形成模型选型依据。

### 5. 权限与安全

- [ ] OCR 前完成用户和知识空间权限校验，私有资料不得进入公共任务或公共缓存。
- [ ] OCR 服务只接收短期、不可猜测的内部文件引用或受控上传，不接收任意外部 URL。
- [ ] API key、Cookie、原始私有正文和个人信息不得写入仓库或普通日志。
- [ ] OCR 输出继承原文档的访问范围、删除策略和审计信息。

## 验收标准

- 扫描版或图片型 PDF 完成 OCR 后可被检索，并能返回正确文件名和页码。
- 手写体、公式和表格的失败或低质量结果会被明确标记，不会静默进入索引。
- 重复提交、服务超时和进程重启不会产生重复索引或丢失原文件。
- 用户删除资料后，OCR 文本、切块、索引、缓存和临时图片均不可再访问。
- OCR 服务不可用时，普通文本型 PDF 的现有导入和检索流程仍能正常工作。

## 边界说明

TXT 与 Markdown 属于原生文本导入，不需要 OCR。当前 Demo 的上传接口仍只接受 PDF；后续应单独增加 TXT/Markdown 的文件类型校验、解析器、内容预览与测试。阅读器的文本字号控制可直接复用于这些格式。
